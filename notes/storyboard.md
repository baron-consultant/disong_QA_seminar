# 2분기 세미나 발표 구성 초안

가정: 사내 구성원 대상, 18분 + 질의응답. 행사명은 ‘2분기’, 자료 기준일은 2026-09-21로 구분한다.

핵심 메시지: **문의가 들어온 뒤 해결되고 안내될 때까지, 하나의 흐름으로 관리한다.**

## 화면 방식

기본은 **3840×2160 발표 + 3840×2160 레퍼런스**다. 전체 화면은 7680×2160, 32:9이며 반으로 나누면 각각 익숙한 16:9가 된다.

왼쪽에는 한 문장과 핵심 설명, 오른쪽에는 그 문장을 뒷받침하는 화면 또는 도식을 둔다. 청중이 읽어야 하는 상세 Markdown 원문은 띄우지 않고 발표자가 필요한 부분만 발췌해 보여준다.

표지·전체 업무 흐름·마무리는 전체 폭, 기능 설명은 분할 보기를 권한다. 화면 폭이 작아지는 노트북 미리보기는 같은 슬라이드를 축소해서 보여주며 실제 발표장의 뒷자리 가독성은 현장 확인이 필요하다.

총 18분. 기술 청중이면 9–10번을 늘리고, 일반 사용자 중심이면 4–8번의 화면 설명을 늘린다.

## 시연 대본 초안

1. 가상 문의 ‘EG-BIM 작업 중 오류’를 작성한다. 제목·내용·첨부·비밀글을 짚는다.
2. 접수 결과의 식별자와 상태를 확인한다.
3. 관리자 목록에서 같은 문의를 찾아 담당자를 지정한다.
4. 고객에게 공개할 답변과 담당자 내부 재현 메모를 각각 설명한다.
5. 개발이 필요하다는 상황을 가정하고 이슈와 Gitea를 연결한다.
6. 이슈 완료와 피드백 완료가 다른 이유를 설명한다.
7. 처리 완료 안내와 작성자의 확인으로 마무리한다.

API가 연결되지 않은 외부 작성 UI를 사용할 경우 ‘화면 흐름 시연’이라고 표시하고, 관리자 반영·실발송을 같은 실행의 결과처럼 이어 붙이지 않는다. 네이버웍스 실발송은 확인된 환경에서만 시연한다. 카카오·SMS는 후속 구현으로 설명한다.

## 발표에서 예상되는 질문

| 질문 | 답변 방향 |
| --- | --- |
| 기존 ABC와 무엇이 다른가? | 기본 수집·분류 기반 위에 BARON-SSO, 통합 관리, 담당자 협업, Gitea, 완료 흐름을 사내 업무에 맞춰 확장 |
| 여러 서비스의 데이터가 모두 보이나? | 관리자에게 권한이 있는 프로젝트를 통합 조회. 모든 사용자에게 전체 공개하는 구조가 아님 |
| 이슈가 끝나면 문의도 끝나는가? | 작업 완료와 고객 안내·확인은 별도로 관리 |
| AI가 자동 답변하는가? | 기본 제품에 AI 설정은 있으나, 이 플랫폼의 자동 답변 운영을 확인한 자료는 없음 |
| 알림은 지금 동작하는가? | WORKS 구현 기록과 실발송 검증을 구분. 외부 카카오·SMS는 추가 구현 범위 |
| 이미 모든 서비스를 연결했나? | 확장 구조와 실제 연결 서비스 수는 구분. 자료만으로 전체 연결 완료를 주장하지 않음 |

## 후속 제작 자료

- 실제 사용자 작성·접수·상세 화면
- 관리자 통합 목록과 피드백 상세
- 공개 답변과 내부 메모 비교
- 이슈와 Gitea 연결 화면
- 완료 안내와 사용자 확인 화면

현재 HTML은 문서 내용을 배치한 검토용 초안이며, 오른쪽 그림은 설명 도식이다.
