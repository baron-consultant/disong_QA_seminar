# 5분 발표 대본

## 흩어진 요청을 한곳으로: Q&A 통합 플랫폼 구축

- 발표자: 송대일 선임연구원
- 발표 시간: 약 5분
- 구성: 표지 포함 플랫폼 소개 약 1분 30초, 구축 과정과 고민 약 2분 55초, 마무리 약 35초
- 말하는 속도와 화면 전환에 따라 페이지별 시간은 조금 조정

## 표지 — 10초

안녕하세요. 송대일 선임연구원입니다. 오늘은 Q&A 통합 플랫폼을 어떤 필요에서 시작했고, 실제 운영에 맞추기 위해 어떤 고민과 변경을 거쳤는지 말씀드리겠습니다.

## 1페이지 — 여러 서비스의 문의를 한곳에서 관리 — 20초

EGBIM, TOVA, GAIA처럼 문의를 작성하는 곳은 서비스마다 다를 수 있습니다. 하지만 접수된 문의를 확인하고, 담당자를 정하고, 답변하거나 개발이 필요한 일에 대한 이슈를 연결하는 과정은 한 관리 공간에서 이어지도록 만든 것이 이 플랫폼의 핵심입니다.

## 2페이지 — 작성 화면과 관리 화면의 역할 — 25초

문의 작성 화면과 관리 화면은 역할을 나눴습니다. 사용자는 각 서비스의 Q&A에서 문의를 작성하고, 작성 내용은 화면 사이의 연결을 거쳐 관리페이지 서버에 저장됩니다. 사용자는 서비스에 맞는 화면을 이용하고, 담당자는 한 관리 공간에서 문의 내용을 확인할 수 있도록 한 구조입니다.

## 3페이지 — 문의가 접수된 뒤의 두 가지 흐름 — 35초

문의가 들어온 뒤에는 크게 두 가지 흐름이 있습니다. 기존 안내나 담당자 답변으로 해결할 수 있는 문의는 확인 후 작성자에게 답변합니다. 개발이 필요한 문의는 담당자가 관련 이슈를 생성해 gitea에 연결하고, 처리 결과를 확인한 뒤 Q&A 답변으로 안내합니다. 문의를 받는 것에서 끝나지 않고, 답변이나 후속 작업까지 이어지도록 흐름을 나눴습니다. 여기까지 제가 구축한 시스템에 대한 간략한 설명이었구요. 다음은 제가 이걸 구축하기까지의 과정 중 발생한 고민과 해결방향을 잡은 경험을 소개하겠습니다

## 4페이지 — 작성 화면만으로는 남았던 운영 문제 — 40초

처음 구상은 홈페이지에 Q&A 작성 화면을 하나 만드는 것이었습니다. 그런데 작성 화면을 만들고 나니 그 다음 문제가 보였습니다. 접수된 글을 누가 확인하는지, 담당자는 어디서 정하는지, 답변과 처리 상태는 어떻게 관리하는지가 정해져 있지 않았습니다. 문의를 받는 기능만으로는 실제 운영을 이어가기 어렵다는 점이 첫 번째 고민이었습니다.

## 5페이지 — 별도의 관리 공간을 마련 — 45초

그래서 작성 화면만 더 키우는 대신, 문의를 처리할 관리 공간을 분리하는 방향으로 바꿨습니다. 관리페이지에는 기존 ABC UserFeedback을 활용해 문의 목록과 담당자, 답변, 처리 상태를 다룰 수 있도록 했고, 처음에는 작성 화면도 같은 서버 안에 연결했습니다. 이 과정에서 화면을 만드는 일과 접수 이후의 운영 방식을 함께 정해야 한다는 것을 확인했습니다.

## 6페이지 — 서비스가 늘어날 때를 고려한 구조 변경 — 55초

다음 고민은 작성 화면을 어디에 둘지였습니다. 처음에는 관리페이지와 같은 서버 안에 두었지만, SSO 로그인을 적용하고 서비스별로 넓혀갈 가능성을 고려하면서 설계를 다시 살펴봤습니다. 바론 홈페이지 안에 Q&A를 직접 붙일지, 서비스마다 별도 작성 페이지를 둘지도 비교했습니다. 결국 작성 페이지는 각 서비스에 맞게 따로 둘 수 있도록 하고, 작성 내용은 중간 연결 기능을 통해 관리페이지 서버로 보내는 방향을 선택했습니다. 처음 정한 구조를 고집하기보다 로그인 방식과 서비스 확장 조건을 확인하면서 설계를 바꿔간 경험이었습니다.

## 7페이지 — 알림 대상에 따른 전달 방식 — 35초

운영 요구는 알림으로도 이어졌습니다. 사내 담당자와 사내 문의자에게는 네이버웍스 알림을, 외부 문의자에게는 카카오 알림톡이나 문자를 제공하는 방향으로 대상을 나눴습니다. 여기서도 먼저 고민한 것은 어떤 기능을 더할지가 아니라, 누가 어떤 상황에서 안내를 받아야 하는지였습니다. 알림 요구가 추가되면서 처리 흐름도 더 구체적으로 정리됐습니다.

## 마지막 페이지 — 기대 효과와 마무리 — 35초

마지막으로 정리하자면 서비스별로 들어온 문의를 한 관리 화면에서 확인할 수 있고, 담당자와 처리 상태를 함께 보며 문의가 어디까지 진행됐는지 파악하기 쉬워지며  답변으로 해결할 문의와 개발이 필요한 요청을 구분해 결과 안내까지 이어갈 수 있습니다. 이런 흐름이 문의를 다시 찾고 전달하는 수고를 줄여 업무를 더 효율적으로 처리하는 데 도움이 되길 기대합니다. 실제 효과는 사용 과정에서 확인하고 보완해가겠습니다. 감사합니다.

## 발표 전 확인 메모

- 알림 기능의 실제 적용 범위가 채널별로 다르면, 해당 채널은 “현재 제공” 또는 “확장 예정” 중 사실에 맞는 표현으로 조정
- Cloudflare Worker, API, SSO는 발표에서 구현 기술 설명으로 길게 다루지 않고, 화면과 관리페이지를 연결하기 위한 배경으로만 언급
- 실제로 측정하지 않은 시간 절감이나 처리율 개선 수치는 제시하지 않기
- 개인의 성과보다 요구가 추가될 때마다 운영 흐름을 다시 살펴보고 설계를 조정한 과정에 초점
