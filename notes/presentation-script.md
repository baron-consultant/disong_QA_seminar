# 5분 발표 대본

## 흩어진 요청을 한곳으로: Q&A 통합 플랫폼 구축

- 발표자: 송대일 선임연구원
- 기준 자료: `docs/index4.html`에 현재 표시되는 페이지
- 목표 시간: 약 5분, 시연 영상 약 24초 포함
- 흐름: 플랫폼 소개와 영상 → 작업 중 마주친 문제와 해결 과정 → 기대 효과와 도전 메시지

## 표지 — 약 10초

안녕하세요. 송대일 선임연구원입니다. 오늘은 Q&A 통합 플랫폼을 만드는 과정에서 처음 생각과 달라졌던 점, 그리고 그때마다 어떤 선택을 했는지 말씀드리겠습니다.

## 1페이지 — 플랫폼 소개와 시연 — 약 45초

먼저 플랫폼 역할을 짧게 소개하겠습니다. 문의는 각 서비스의 Q&A에서 작성하고, 담당 확인과 답변, 필요한 개발 요청은 통합 관리페이지에서 이어집니다. 오른쪽 화면의 관리 화면을 클릭해 시연 영상을 보겠습니다.

> **시연 동작:** 오른쪽 참고 화면을 열고 관리 화면 이미지를 클릭해 영상 창을 띄운 뒤, 영상 창에서 재생 버튼 클릭 — 약 24초

영상에서는 문의를 작성한 뒤 관리 화면에서 확인하고 처리하는 순서를 보실 수 있습니다. 이제 이 구조가 처음부터 정해져 있었던 것은 아니고, 작업을 진행하며 어떤 문제를 발견했는지 말씀드리겠습니다.

## 2페이지 — 작성 화면만으로는 부족했던 점 — 약 55초

배경부터 말씀드리면, 각 소프트웨어의 홈페이지가 바론 홈페이지로 통합되면서 사용자 화면은 별도 업무 처리를 맡지 않는 정적 페이지 중심으로 구성돼 있었습니다. 기존 페이지에서는 사용자가 문의를 작성하는 영역과 담당자가 확인하고 대응하는 관리 영역도 한곳에 뒤섞여 있어 Q&A를 체계적으로 처리하기 어려웠습니다. 문의 작성 화면만 두는 것으로는 이 문제를 해결할 수 없었습니다. 작성된 문의를 확인하고, 담당자를 정하고, 답변과 진행 상황을 관리할 별도의 Q&A 관리페이지가 필요했습니다. 이 필요에서 플랫폼 개발을 시작했습니다.

## 3페이지 — 관리할 자리를 만들고 작성 화면 연결 — 약 55초

그럼 관리페이지를 어떻게 만들 것인가가 다음 질문이었습니다. 필요한 기능을 처음부터 하나씩 모두 만들 수도 있었지만, 그러면 시간이 많이 걸릴 수 있었습니다. 그래서 기본 설정과 관리 기능이 이미 갖춰진 웹 애플리케이션을 활용하기로 했고, 그 기반으로 선택한 것이 ABC UserFeedback입니다. 준비된 관리 기능 위에 Q&A 업무에 필요한 항목과 처리 흐름을 맞춰 통합 관리페이지를 구성해 개발 시간을 줄였습니다. 처음에는 문의 작성 화면도 같은 서버 안에 연결해, 작성부터 관리까지 이어지는 흐름을 마련했습니다. 이 단계에서는 모든 것을 새로 만드는 대신 기존의 준비된 기반을 활용하는 것이 시간과 작업 부담을 줄이는 방법이었습니다.

## 4페이지 — 확장에 맞춰 구조를 나누고 작업을 정리 — 약 65초

3페이지에서 말씀드린 것처럼 처음에는 Q&A 작성페이지와 관리페이지를 같은 서버 안에 두었습니다. 두 화면을 연결해 운영 흐름을 만드는 정도여서 작업 난이도도 높지 않았습니다. 이후 서비스별 확장을 위해 작성페이지는 별도 공간에 두고, 데이터는 API로 관리페이지 서버와 주고받도록 분리하자는 요청이 나왔습니다. 그래서 구조를 다시 설계했습니다. 이때 서비스별 Q&A와 관리페이지가 서로 다른 서버와 작업 디렉터리를 사용하게 됐고, AI Agent에게도 각 디렉터리에서 따로 두 번 지시해야 했습니다. 매번 전체 배경을 다시 설명하는 일을 줄이려고 구조와 공통 규칙, 환경별 작업 항목을 하나의 Markdown 가이드에 정리했습니다. 두 환경에서 Agent에게 작업을 지시할 때 같은 문서를 주고 해당 환경의 task를 지정하니, 각자 다른 곳에서 진행하는 작업도 같은 흐름에 맞춰가기 수월했습니다.

## 마지막 페이지 — 문제 발견에서 작업 방식 수립까지 — 약 70초

마지막으로 2페이지부터 4페이지까지의 과정을 세 가지로 정리하겠습니다. 먼저, Q&A 작성과 관리가 한곳에 섞여 있어 문의 대응이 어렵다는 문제를 발견했습니다. 다음으로, 관리페이지를 처음부터 만드는 대신 기본 기능이 갖춰진 ABC UserFeedback을 활용해 작업 시간을 줄였습니다. 마지막으로, 작성페이지와 관리페이지가 서로 다른 서버와 작업 디렉터리로 나뉘면서 AI Agent에게 각각 작업을 지시해야 했습니다. 공통 구조와 환경별 task를 하나의 Markdown 가이드에 정리해 두 환경의 작업 기준을 세웠습니다.

저는 그동안 PHP로 단일 서버에서 운영되는 단순한 홈페이지를 주로 만들어온 초보 개발자였습니다. 이번 작업도 한 달 남짓한 기간 동안 AI Agent에게 할 일을 구체적으로 전달하고, 결과를 확인하며 진행했습니다. 처음부터 모든 답을 알고 시작한 것은 아니지만, 문제를 나누어 살펴보고 필요한 내용을 문서로 정리하면서 한 단계씩 풀어갈 수 있었습니다. 저도 해냈으니 여러분도 충분히 하실 수 있습니다. 각자 업무에서 불편한 점 하나를 찾아 도전해보셨으면 좋겠습니다. 감사합니다.
